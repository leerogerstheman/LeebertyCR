# LeebertyCR · CRA/CRC 临床试验工作台

**让临床监查员（CRA）与临床协调员（CRC）的日常工作，看得懂、学得会、做得对。**

LeebertyCR 是一个**本地运行、零依赖**的药物临床试验岗位辅助应用：把 CRA/CRC 的工作流程细节与背后理念，
用大白话、流程图、可勾选核查清单、场景练习和案例讲清楚，并把高频工作文件模板与个人任务台
直接给到用户手上。应用标识为**蓝黑底 + 大写哥特体 CR**（见 `web/index.html` 的 favicon 与侧边栏图标）。

---

## 一、快速开始（两条路，任选其一）

```
双击  D:\LeebertyCR\LeebertyCR.exe                   ← 原生应用窗口（推荐）
双击  D:\LeebertyCR\start.bat                        ← 同样启动原生窗口
```

**LeebertyCR.exe 是真正的原生 Windows 桌面应用（WinForms），不依赖任何浏览器**：
双击后出现的是本程序自己的窗口（原生边框、自己的任务栏图标、蓝黑底哥特体 CR 图标），
窗口内部完成登录、导航、核查清单、工作流执行、双要素签名与用户管理。
本地 Node 引擎由窗口自动以隐藏进程启动/管理，普通用户全程无感。

打开后先**登录**（内置演示账号见登录页，统一演示口令 `CRA-Demo-2026!`），
第一屏是首页：确认当前账号身份（CRA / CRC / 研究者 / QA / 管理员），再按三条学习路线进入。

- `start.bat` — 启动原生窗口（等价于双击 exe）
- `stop.bat` — 停止后台实例
- 系统托盘（窗口最小化后）：打开窗口/备份数据/自检/停止退出
- Web 界面（http://127.0.0.1:8816）仅作为**可选的备用访问方式**保留，应用窗口本身不依赖它

环境要求：**只需要 Node.js 18+**（推荐 22+）。零第三方依赖，**断网可运行**。
exe 由 Windows 自带的 C# 编译器现场编译（`scripts/build-exe.js`），不依赖任何第三方组件。

## 二、为什么做这个应用

市面上的临床试验培训材料大多是「法规条款堆叠」，新手 CRA/CRC 最常问的三个问题——
**我到底该做什么？为什么必须这么做？做错了会怎样？**——往往要靠带教老师的口头经验回答。
本工作台把这三件事做成结构化产品：

1. **理念先行**：先讲「为什么」。CRA 为什么存在（监查三大目的）、CRC 为什么存在
   （研究者手下的流程管家）、GCP 十三条原则翻译成人话、ALCOA+ 数据完整性八个字母配反例。
2. **流程可见**：一个试验从中心调研到归档的 **8 个生命周期阶段**，每阶段回答
   「目的 / 谁做什么 / 产出什么 / 常见的坑」。CRA/CRC 各 **15/14 张任务卡**，
   每张回答「为什么 / 何时 / 怎么做 / 要点 / 红线 / 法规依据」。
3. **执行可落地**：**10 张可勾选核查清单**（163 项，含关键项强制提醒与进度保存）、
   **7 份文件模板**（监查报告、随访信、SDRP…一键复制）、**任务台**管理现场待办、
   **24 道场景练习**即时判题解析、**5 个教学案例**复盘真实问题、**57 条术语中英对照**。

设计理念与 GxP-Workbench 一脉相承：**内容是数据不是代码**（`seed/*.json` 可自行扩展）、
**界面直白**（职责写在图上，不藏在悬浮提示里）、**留痕可追溯**（勾选与任务保存在本机文件）。

## 五、工作流执行模块（参照 GxP-Workbench 引擎）

与 GxP-Workbench 的 `src/domain/workflow.js` 同构：**流程定义是数据，引擎是唯一状态机**。
新增流程 = 往 `seed/workflows.json` 加一个定义，不写代码。

```
受控记录 = 一串有顺序、有角色门槛、部分需签署确认的步骤
```

**推进步骤时的五道门**（错误码与 GxP 一致）：

| 顺序 | 门 | 含义 | 错误码 |
|---|---|---|---|
| 1 | 终态检查 | 已关闭/取消的记录不可再改 | `RECORD_TERMINAL` |
| 2 | 步骤顺序 | 只能执行当前步骤 | `STEP_OUT_OF_ORDER` |
| 3 | 角色门 | 当前身份必须在步骤允许角色内（CRA/CRC/研究者/QA） | `ROLE_NOT_PERMITTED` |
| 4 | 独立复核门 | 提出人不得执行 🔒 独立复核步骤（Annex 11 §12.1） | `INDEPENDENCE_VIOLATION` |
| 5 | 签名门 + 必填字段 | ✍️ 签名步骤需姓名+勾选声明；必填项齐全 | `SIGNATURE_REQUIRED` / `STEP_FIELDS_MISSING` |

8 条流程：

| 流程 | 前缀 | 步骤 | 特色 |
|---|---|---|---|
| 知情同意与受试者权益事件 (GCP-IC) | IC | 5 | 签署日期 vs 试验操作日期核查；独立关闭 |
| 临床试验方案偏离 (GCP-PD) | PD | 5 | 重要偏离判定；独立关闭 |
| 监查访视闭环 (MON-CYCLE) | MV | 6 | 计划→核对→确认→随访信(签名)→整改→复核关闭 |
| SAE 上报与跟踪 (SAE-TRACK) | SAE | 6 | 获知时限→上报申办者(24h 演练)→伦理→医学评估(研究者签署)→结案 |
| 药物温度偏差/账实差异 (IP-TEMP) | IPT | 5 | 发现即隔离→申办者处置决定→独立关闭 |
| 中心启动流程 (SITE-OPEN) | SO | 5 | 四件套(批件/授权/文件/药品)+独立放行 |
| 中心关闭流程 (SITE-CLOSE) | SC | 4 | 数据→药物→文件→独立确认 |
| 数据质疑闭环 (QUERY-DATA) | QR | 5 | 接收→回源→答复→研究者确认(签名)→复盘 |

**执行方式**：新建记录（以当前身份为提出人）→ 按步骤推进。界面在每步显示「引导语 + 表单 +
参与身份」；角色门未过时给出切换身份按钮（举例：CRA 提出的知情同意事件，关闭步骤要求
QA/研究者执行，正是 GxP「提出人不能自己关闭」的教具）；签名步骤输入姓名并勾选声明；
所有动作（创建/完成步骤/签署/取消）进入只追加的活动历史。首次运行自动生成 2 条演示记录
（可删除），记录存在 `data/records.json`。

## 六、登录与权限系统（参照 GxP-Workbench core/auth.js + rbac.js）

**登录门禁**：打开应用先登录（21 CFR Part 11.10(d)——仅限授权人员访问）。账号决定角色，角色决定权限。

| 能力 | 实现 | 法规依据 |
|---|---|---|
| 账号库 | `data/accounts.json`；内置 5 个演示账号（admin / demo_cra / demo_crc / demo_pi / demo_qa），统一演示口令见登录页与启动横幅 | 唯一登录（Annex 11 §12.1） |
| 口令存储 | scrypt（N=16384, r=8, p=1）+ 随机盐；拒绝弱口令（长度/字符类别/常见口令/含用户名/历史复用） | 21 CFR Part 11.300(b) |
| 失败锁定 | 连续 5 次错误 → 锁定 15 分钟；锁定期间正确口令也拒绝；管理员重置口令解锁 | 21 CFR Part 11.10(d) |
| 会话 | HttpOnly + SameSite=Strict Cookie；空闲 30 分钟 / 绝对 12 小时超时；改密/重置/禁用即撤销全部会话 | Annex 11 §12.3 |
| 首次建号 | `CRA_BUILTIN_ACCOUNTS=0` 启动 → 登录页变为「创建第一个管理员」流程 | GxP 同款 |
| 电子签名 | **双要素**：要素 A 标识码+口令（重新输入，不复用会话）；要素 B 一次性挑战码（120 秒、单次、按人） | 21 CFR Part 11.200(a)(1)(i) |
| 签名内容 | 打印姓名、时间、含义（封闭枚举）、说明，关联到记录步骤，且进入历史与安全日志 | 21 CFR Part 11.200(a)(2)(3) |
| RBAC | 5 角色 × 13 权限矩阵，路由级强制 + 步骤角色门服务端强制；admin 持 `*` 但不参与 GxP 记录签署 | Annex 11 §12.1 |
| 状态隔离 | 核查清单/练习成绩/任务台按账号存 `data/users/<用户名>/state.json`；匿名会话仅内存不持久化 | 职责分离 |
| 安全日志 | `data/security.log` 只追加：登录成功/失败/锁定、挑战码签发、签名、用户管理操作；admin/QA 可查 | ALCOA+ Enduring |
| 记录删除 | 记录不可删除（GxP 审计可辩护性）；仅管理员可删**演示**记录 | ALCOA+ |

**切换身份 = 退出登录后换账号登录**（GxP 身份切换同款）：工作流步骤的角色门比较的是账号角色，独立复核门比较的是提出账号——这正是「提出人不能自己关闭」的教具。
