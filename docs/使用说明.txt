  LeebertyCR · CRA/CRC 临床试验工作台 · 使用说明
════════════════════════════════════════════════════════════

【这是什么】
一个装在 D 盘（D:\LeebertyCR）、完全在本机运行的程序，帮助您理解并执行
药物临床试验中临床监查员（CRA）与临床协调员（CRC）的工作：流程是什么、
为什么这么做、具体怎么做、有哪些红线，还提供可勾选的核查清单、任务台
和文件模板。应用标识：蓝黑底 + 大写哥特体 CR。

【怎么启动】
方法一（推荐）：双击  LeebertyCR.exe
                 → 弹出的是【原生应用窗口】（WinForms，自己的窗口/图标/托盘，
                   不依赖任何浏览器，也无须打开网页）
方法二：双击  start.bat（等价于双击 exe）
本地引擎由窗口自动以隐藏进程启动；窗口最小化后可从托盘恢复；
托盘右键 →「停止并退出」或双击 stop.bat 停止。
（可选：若想用浏览器打开备用网页界面，访问 http://127.0.0.1:8816——
  这只是备用入口，应用窗口本身不依赖它。）

【登录（新增）】
打开后先登录（仅限授权人员访问）。
内置演示账号（统一演示口令：CRA-Demo-2026!）：
  admin      系统管理员（管用户和权限，不参与记录签署）
  demo_cra   林晓 - CRA 临床监查员
  demo_crc   陈语 - CRC 临床协调员
  demo_pi    王建军 - 主要研究者
  demo_qa    赵敏 - QA 专员（独立复核）
点登录页的身份卡可自动填入用户名。
口令错 5 次会锁定 15 分钟；想换身份 = 退出登录，再用别的演示账号登录。
不需要演示账号？用 CRA_BUILTIN_ACCOUNTS=0 启动，首次会走「创建管理员」流程。

【怎么停止】
· 托盘图标右键 →「停止并退出」；或
· 关闭 start.bat 的控制台窗口；或
· 双击 stop.bat

【第一次打开做什么】
1. 首页点选您的身份：CRA 临床监查员 / CRC 临床协调员 / 研究者 / 旁观学习
2. 按「新手上路」三条路线走：理念课堂（为什么）→ 试验生命周期（全局）
   → 岗位手册 + 核查清单（怎么做）
3. 用「场景练习」检验理解，用「任务台」管理自己的现场工作

【您的数据存在哪里】
个人进度按账号存放：data\users\用户名\state.json（核查清单勾选、练习成绩、任务台）。
管理员在「账号与权限」页管理用户（建号/禁用/重置口令/删除）。
安全日志在 data\audit-chain.jsonl，它是**哈希链**：每条记录都带前一条的指纹，
任何被改动、删除或插入的行都会在校验时暴露（界面上标红并给出断点序号）。
管理员和 QA 可在「账号与权限 → 安全日志」看到「审计链：完整 ✓（N 条）」。
想用命令行核验：node scripts\verify-audit.js
工作流记录在 data\records.json，版本快照在 data\record-history.jsonl（可回看任一版本）。
受试者在 data\subjects.json，文档在 data\documents.json。
备份 = 复制整个 data 文件夹；恢复 = 把备份文件放回 data 文件夹。

【新增：受试者登记册（P1）】
侧边栏「🧑🤝🧑 受试者登记册」：
· 登记受试者：只填「中心 + 3~6 位数字编号」——**填姓名或身份证号会被拒绝**（伪匿名原则）
· 来访视：给受试者排访视（计划日期 + 允许窗口 + 绑定 eCRF 表单）
· 录入 eCRF：双击访视行，按表单填数据；保存时系统做**逻辑核查**
  （必填、数值范围、枚举、日期格式、跨字段矛盾），**不通过就不入库**——
  这就是真实系统里 Edit Check 的作用
· 访视日历：一眼看到临期与逾期访视（逾期标红），可导出 .ics 导入
  Outlook / Google 日历
· 入组漏斗：筛选 → 知情 → 入组 → 随访 → 完成，附带筛选失败率、知情同意率

【新增：eTMF 文档台账（P2）】
侧边栏「📁 eTMF 文档台账」：
· 建档：选文件类别（来自 ICH E6(R2) 必需文件清单）+ 责任人 + 复核到期日
· 生命周期：草稿 → 待审 → 已批准 → 已被替代 → 已归档
  —— 不能跳级（比如待审不能直接归档），系统会拒绝并说明允许的下一步
  —— **批准人不能是建档人**（职责分离），换个账号才能批准
· 版本链：每次修订/流转都会留下「谁、何时、因为什么」
· 缺口扫描：对照 18 项必需文件，告诉您「缺哪些」「哪些有文件但没批准」，
  给出建档就绪度百分比，可导出 CSV

【新增：导出与打印（P0）】
· 核查清单页：「⬇ 导出 CSV」把清单条目、关键项、勾选状态、怎么做、为什么导出
· 工作流记录页：「📚 版本历史」（回看任一版本当时的样子）、
  「⬇ 导出 CSV」、「🖨 打印报告」（直接调用打印机）
· SAE 追踪记录额外有「📤 生成 SAE 报送稿」和 **24 小时时限计时条**
  （填写「首次获知时间」后自动倒计时，超时标红提醒）

【常用问题】
· 端口被占用？→ 设 CRA_PORT=8817 再启动
· 需要联网吗？→ 不需要，完全离线运行
· 能改内容吗？→ 可以：seed 文件夹下的 JSON 就是全部文字内容（含 eCRF 表单
  forms.json），改完重启生效
· 能多人一起用吗？→ 单机多账号（切换登录即切换身份）；若要多人同时用浏览器
  访问，可用附带的 Dockerfile / docker-compose.yml 起服务端版
· 内容有法律效力吗？→ 没有。本应用是学习与工作辅助工具，实际执行
  以现行法规、试验方案、伦理要求与本单位 SOP 为准

【工作流怎么用】
侧边栏「🌀 工作流执行」→ 流程库选一个流程（如：知情同意事件、方案偏离、
监查访视闭环、SAE 上报）→ 「新建记录」填表 → 按步骤推进：
· 每一步会显示「引导语 + 表单 + 需要哪个身份执行」
· 身份不对？左栏切换身份（CRA/CRC/研究者/QA）再继续——有些步骤专门
  要求「与提出人不同的身份」执行（独立复核，这是 GCP 的职责分离理念）
· 带 ✍️ 的步骤要输入姓名并勾选声明（签署留痕）
· 每一步的完成、签署、取消都会记入「活动历史」
首次打开时会自动生成 2 条演示记录，方便立刻体验，可以随时删除。
